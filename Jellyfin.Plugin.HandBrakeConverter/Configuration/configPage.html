Original files checks, undo, files on hold
Rules for looking after your original files: what to check before and after a conversion, and how long replaced originals are kept so you can undo them. Whether a library keeps or replaces its originals is chosen in Conversion settings (or a library's own settings) under "Original file".

1. Before converting

Handy for ignoring tiny clips and samples.
A conversion only starts if the disk has room for the new file plus the spare space below. Otherwise it waits.

2. After converting: checks before anything is replaced

A converted file that fails a check is thrown away and the original is left exactly as it was.
Skipped for manual conversions that keep the original or burn in subtitles, since those are deliberate.
For example an H.265 file when the encoder is H.265: re-encoding it takes hours and mostly loses quality; titles you convert by hand are always converted.
A hard link is one file with two names, for example a library file shared with a download folder. In place writes the converted video into that one file, so both names shrink and no space is wasted; the downside is that the other name (a torrent still seeding it, say) no longer matches its original. It needs room for a temporary copy of the old file while it writes, and the old file is held for your "keep replaced originals" days as a real copy. Does not apply when you keep the original, or when the file type changes (that makes a new file).
Example: 20% means a 10 GB original is only replaced if the result is 8 GB or less. A result that saves less is discarded and the original kept.
Compares the length, audio tracks, subtitle tracks, chapters and (when kept) HDR with the original, and throws the result away if anything is missing. Uses the ffprobe that comes with Jellyfin.

3. Replaced originals

When a library is set to Replace original, the old file is moved (not copied) into a hidden folder instead of being deleted, so you can undo a bad conversion. By default that folder is .hb-originals inside the same library folder, on the same drive as the video: the move is instant and writes nothing to your system disk, and Jellyfin skips the folder.
Off = the old file is deleted right away (no undo). On = it is held, then deleted automatically after the number of days below. Either way, subtitle files that sat next to the old file (such as Name.eng.srt) are deleted together with it, but only those in a language the converted video still has; any other subtitle file is left alone.
Blank = the automatic hidden folder described above (recommended). If you set your own, pick a folder on the same drive as your videos, outside your libraries; on a different drive every original is copied across, which is slow and wears that drive.

Currently on hold

Restore puts the original back next to the converted file as "Name - Original", which Jellyfin shows as a second version.
Schedule & performance when it runs, pausing for viewers
Choose when conversions are allowed to run, and how they behave while running, such as pausing when someone is watching. Leave time limits off to convert whenever there is something to do.

When to convert

Set the days and hours when conversions may run.
Off = conversions run whenever there is something to convert (they still pause while someone is watching, if you leave that on below).
Add one or more time windows (server local time). Conversions only run inside a window. Example: every day 23:00 to 10:00. A window that ends earlier than it starts runs past midnight.
Decides what happens to a conversion that is still running when your time window closes.

Days when nothing runs

Optional date ranges to skip completely (holidays, travel).

While converting

How conversions behave while they are running, so they don't get in the way of watching.
The conversion freezes while anyone is playing something in Jellyfin and carries on when they stop. A file is never swapped while someone is watching that exact title.
Normally a paused video doesn't stop a conversion. Turn this on if it should.
Listening to music won't pause conversions, because it uses very little server power.
Gives other programs on the server (including Jellyfin streaming) first call on the CPU, so the server stays responsive. Conversions take a little longer when the server is busy. Recommended.
Leave at 1 unless the server has plenty of spare CPU and fast disks: each extra conversion shares the same processor, memory and disk, so on an older machine two at once is usually slower overall and can make streaming stutter. The free-space check counts every conversion that is running.
If HandBrake goes completely silent for this long it is treated as frozen: it is stopped and recorded as failed (the original is untouched) so the queue can carry on. Time spent paused or waiting for viewers does not count.

Encoder test
Lists the video encoders this HandBrake offers on this server and proves each one works with a 2-second sample encode (a few seconds each; your library is not touched and the sample is deleted). Hardware encoders (NVENC for NVIDIA, QSV for Intel) only appear when HandBrake finds the hardware, and can be listed even when the driver is broken, which is what the test catches.
Encoders that fail are marked "- not supported" in every Video encoder dropdown and are never suggested; encoders that pass or were never tested are left unmarked.

Update suggestions
Every time Jellyfin has to convert a video while someone watches, it writes a log. This reads the newest ones (up to the number below), shows what each one says Jellyfin had to change (video, audio, subtitles), and works the "(suggested from your playback)" marks in the dropdowns out again from that. Nothing is changed in your settings; the marks only point at a choice.
Repair giant subtitles
Earlier versions of this plugin could leave subtitles that some players draw giant (a line can fill a quarter of the screen): MP4 text that kept a styled track's font size, and SRT carrying font size tags. This looks through every MP4 and MKV in your libraries (and the .srt files next to them) and repairs what it finds: the text keeps its lines, timing and italics but loses the stored font size, so it is drawn at your Jellyfin subtitle size (in MP4 files the subtitles become .srt files next to the video). The video and audio are not touched and nothing is re-encoded; the replaced file is held in Original files like any other.
